# SKILL & ATLAS AUDIT — `shredded-shape` v1.4.0 (2026-11-17)

> **Scope:** 6 `skills/*/SKILL.md` descriptions, 4 `agents/*.md` subagents, `rules/frontend-9-axes-guidelines.md`, 3-file Atlas (`assets/*`), validators/sync scripts, and the `.context` State files.
> **Method:** Full read of all L1/L2 artifacts, line/description budget measurement, cross-check of AGENTS.md claims vs. actual files, and live re-execution of the declared verification commands.

## 1. Executive Summary

The suite is **operationally healthy and unusually well-instrumented**: every declared gate was re-run during this audit and passed. The findings below are therefore **coherence and maintainability defects**, not functional failures — documentation drift, naming/structure mismatches, undeclared external dependencies, and one real budget contradiction that the validator cannot currently catch.

**Description budgets (L1, cap 450 chars):** all 6 skills + 4 agents within budget (256–392 chars). **L3 references:** all 16 files `<= 150` lines (max 120). **File caps:** all `<= 600` lines except none violated at the 600 threshold; see I1 for the 520 contradiction.

## 4. Incoherences Found

### I1 — Atlas line-budget contradiction (context vs. spec vs. reality) — **P1**
- `.context/context.md` §1: Atlas files "`<= 520` lines each". `.context/spec.md` §1: "`<= 600` lines each". Actual `assets/atlas_app.js`: **537 lines** — violates the 520 claim, passes the 600 claim. The validator enforces only 600 (`CODE_CAP_EXTS` check in `_check_parity_and_line_caps`), so the stricter documented budget is unenforceable and already broken.
- **Why it matters:** two SSOT files disagree on a quantitative invariant; the next contributor cannot know which budget is real, and the changelog (v1.4.0 rail/`base-select` work) already pushed the JS past 520.
- **Fix:** pick one number — recommend **600** (aligns with the global `<= 600` module rule) — update `context.md`, and either drop the 520 claim or add an explicit per-file budget check to the validator if 520 was intentional.

### I2 — Validator output does not match documented claim — **P2**
- `AGENTS.md` §0 and `.context/spec.md` §3 claim the validator reports "`6/6` skills, `4/4` subagents". Actual stdout: `shredded-shape validation: 6/6 skills | errors=0` — subagents are validated (errors would fail the run) but never counted in the summary.
- **Fix:** have `validate_ecosystem` return an agent pass-count and print `6/6 skills | 4/4 subagents | errors=0`. One-line change; restores claim/reality parity.

### I3 — AGENTS.md skill-mapping table is a stale subset of agent YAML — **P1**
- `AGENTS.md` §1 maps each stage to 2–3 "Core Skills", but the agent frontmatter declares more: `ui-analyst` also binds `chrome-devtools`, `a11y-debugging`, `debug-optimize-lcp`, `memory-leak-debugging`, `modern-web-guidance`; `ui-planner` also binds `complex-zero`, `modern-web-guidance`; `ui-worker` also binds `modern-web-guidance`; `ui-judge` also binds `clinical-minimalist-ui`, `a11y-debugging`.
- **Why it matters:** the table is the human routing document; anyone reasoning about stage capabilities from AGENTS.md under-counts external dependencies by up to 5 skills (see I4).
- **Fix:** regenerate the table from the YAML (add a `--check` mode to the validator that diffs AGENTS.md §1 against frontmatter `skills:` lists), or extend the table with an "External bindings" column.

### I4 — Undeclared external skill dependencies — **P1**
- Agents/skills hard-reference `modern-web-guidance`, `chrome-devtools`, `a11y-debugging`, `debug-optimize-lcp`, `memory-leak-debugging`, plus REA (`analyze_web_bundle`) and `system-project-auditor`. None are bundled in the plugin, none declared in `plugin.json` (no dependency field), and `.agents/skills.json` `include_only` lists a *different* set (`vercel-react-best-practices`, `web-design-guidance`, `ai-sdk`, `live-api-function-auditor`) that overlaps zero of the actual bindings.
- **Mitigation present:** SKILL.md prose documents L3 offline fallbacks, so degradation is graceful.
- **Why it matters:** on a fresh machine the 4 agents advertise skills that do not resolve; `.agents/skills.json` actively misrepresents the suite's needs.
- **Fix:** add an `externalSkills` (optional-deps) section to `plugin.json` or README, correct `.agents/skills.json`, and add a validator warning when a bound skill is neither local nor declared.

### I5 — "9-Axis" rules file does not contain 9 axes — **P2**
- `rules/frontend-9-axes-guidelines.md` is named/described as "9-Axis SSOT" but the body enumerates **5 numbered items**; the 9 axes are nowhere identifiable. The file is also 22 physical lines with single lines up to **1,429 chars** — technically within the 24 KB cap, practically unreviewable in diffs.
- **Fix:** restructure into 9 explicit `### Axis N — <name>` sections (the content already exists: tokens, depth, matte finish, archetypes, spacing, layout, motion, a11y/ergonomics, FSM/security). Why: the AGENTS.md and frontmatter both sell "9-Axis" as the public contract; the document must make the 9 enumerable.

### I6 — "State Triad" names only two files — **P2**
- `AGENTS.md` §0: "**State Triad:** `.context/context.md` | `.context/spec.md`" — a triad of two; header also cites an unexplained `Triad v2.1` version.
- **Fix:** either add the third state file (`AGENTS.md` itself is the natural third leg) or rename to "State Pair" and define/drop `Triad v2.1`.

### I7 — Sync script is machine-bound and carries a dead key — **P2**
- `scripts/sync_shredded_shape.py` hardcodes `DEFAULT_GEMINI_ROOT = C:\Users\melki\.gemini` and returns `"triad_mirrored": 0` unconditionally (legacy field, never set).
- **Why it matters:** contradicts the "standalone repository" goal — any other machine syncs into a nonexistent path or the wrong user profile.
- **Fix:** resolve the Gemini root from `GEMINI_CONFIG_HOME`/`%USERPROFILE%` with a CLI override, and remove or implement `triad_mirrored`.

### I8 — Skill↔agent naming asymmetry — **P3**
- `ui-frontend-analyst`→`ui-analyst`, `ui-brand-ux-planner`→`ui-planner`, `ui-clean-worker`→`ui-worker`, `ui-quality-judge`→`ui-judge`. Four distinct rename rules (drop `frontend`, drop `brand-ux`, drop `clean`, drop `quality`) must be memorized.
- **Fix:** low priority — the AGENTS.md table documents the mapping; alternatively adopt a mechanical rule (`ui-<stage>-<role>`) in v1.5.0. Why: every cross-reference (DAG payload, SKILL.md chaining, plans) currently pays a translation tax.

### I9 — Changelog traceability — **P3**
- `context.md` §3 records v1.2.0, v1.3.0, and v1.4.0 **all on 2026-11-17**, the older two as one-line entries.
- **Fix:** backfill one-sentence scope per release. Why: the audit trail is the stated purpose of the changelog section.

### I10 — Repo not fully self-contained — **P3**
- `AGENTS.md` header inherits "Universal Golden Rules (1–8) and the Self-Refine Closing Block" from `quality-efficiency-guidelines.md`, which is **not in this repository** (lives in the user's global config).
- **Fix:** vendor a copy under `rules/` or inline the 8 rules. Why: a fresh clone silently loses the inherited contract that AGENTS.md declares as `always_on`.

## 5. Prioritized Implementation Tips

1. **P1 — Single budget SSOT (I1):** set Atlas cap to 600 everywhere; add validator support for per-path budget overrides only if a stricter cap is ever truly wanted. *Why:* unenforced documentation budgets erode trust in all other documented budgets.
2. **P1 — Generate the AGENTS.md §1 table from agent YAML (I3) + declare external skills (I4):** one new validator function (`check_agents_table_sync`) kills both drift classes at commit time. *Why:* both defects are regenerable-from-source problems; manual tables always drift.
3. **P1 — Fix `.agents/skills.json`:** replace `include_only` with the actual external bindings (`modern-web-guidance`, `chrome-devtools`, `a11y-debugging`, `debug-optimize-lcp`, `memory-leak-debugging`). *Why:* the file currently documents the wrong dependency set to any host that reads it.
4. **P2 — Validator summary counts subagents (I2).** Trivial; closes the AGENTS.md claim gap.
5. **P2 — Restructure the 9-Axis rules file into 9 headed axes (I5).** *Why:* the glob-triggered file is the most frequently injected document in the suite; its public name must be enumerable in its body, and sub-1,400-char lines make every future diff unreadable.
6. **P2 — Portable sync root + dead-key cleanup (I7).**
7. **P3 — Naming convention decision (I8), changelog backfill (I9), vendor inherited rules (I10).**

- Read-only sandbox isolation of Stages 0/1/3 enforced both in YAML and by the validator (`READ_ONLY_AGENTS` check).
- Mirror parity (`agents/` vs `.agents/agents/`, vendored `_ss_core.py`) is machine-checked, not convention-checked.
- The Atlas is a genuine living SSOT demo: it passes its own gatekeeper at 100/100/100 with zero slop — use it as the reference fixture in docs.
- Description contract (30–450 chars, positive-before-negative triggers, F1 = 1.0 evals per skill) is enforced and tested.
